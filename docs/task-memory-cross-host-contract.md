## 1. 交付边界与已有证据

目标是“Mac 当前任务 → 开发机现有 harness/Botmux → Mac 原聊天”的可解释接力。记忆允许独立离线追加的后续方向，与单个实现任务仅一个活动执行者分开。owner 明确交接执行权，目标核对代码及已确认材料后才开始；收到记录、群里一句“继续”、源端失联都不自动授予执行权。

2026-11-11 的 [hancheng.hc/dev-tracker#661](https://code.byted.org/hancheng.hc/dev-tracker/issues/661) 双端色卡实验说明：四条共同记录、离线各写一条，交换原请求后双方各六条正文，但只有四个 ID 相同，默认 checkpoint 相反。相同 task revision 也不能证明收齐或相同进度。该实验是同步缺口证据，不是本合同八类场景的实现 PASS。单机 Botmux 路由、桌面首轮 Skill 发现和本地幂等分别有用，但不能替代跨机执行交接。

## 2. 交接证据与身份口径

以下是一次交接所需的**语义字段**，保存在项目既有获准交接记录/收据中，不新增数据库或 JSON schema，不要求调用不存在的 CLI。owner 发起时生成稳定交接 ID；同一交接重试沿用它，改变目标/代码/授权范围需新提案。

| 证据组 | 必须核对的内容与已有对象关系 |
| --- | --- |
| 身份与范围 | 任务 task_id、owner、源/目标设备及项目、目标 harness、配对/任务授权证据、允许的工作范围。task_id 是分区，不是权限；名称、目录相同或知道 ID 都不足以授权 |
| 账本与版本 | 每端 ledger 所在主机及受控定位、固定 binary/package/协议身份、各端 task revision、恢复 incarnation/世代及其来源。revision 仅在本端相应世代内比较；v1 没有可证世代时记未知，不伪造字段或复用旧恢复批准 |
| 记忆边界 | 本轮选定的来源记录 ID/修订/信任与当前状态、候选/冲突/遗漏、最后可用快照及摘要、各方向目标上界和连续持久确认位置。对端不通告上界时尾部未知；条数、发送成功和 task revision 不代替回执 |
| 代码边界 | repository 身份、base commit、candidate commit 或完整选定 delta 清单及摘要、staged/unstaged 影响、二进制/删除/相关未跟踪文件、对应测试与证据引用。代码清单与记忆快照明确配对，不能拼不同轮次 |
| 执行与 pending | 当前活动执行者、源端停止/交出回执、owner 对具体目标及范围的开始授权、目标会话/job ID、未决请求的原 key/client/run/time 与已知结果。执行次序可人工编号留证，不是已实现的分布式锁或 fencing |

不把凭据、全量聊天、会话数据库、未选任务或 raw 工具日志当交接正文；只给获准的受控引用。收到的文字/脚本/配置不提供新的命令权限。确认字段沿用原内容授权，不能由目标 harness 或复制程序自动填造。

## 3. 准备、核验、开始、返回

| 阶段 | 进入与退出条件 | 失败时可做什么 |
| --- | --- | --- |
| 准备 | 明确源/目标、所选任务、代码与记忆范围；核对 pending。源端实现执行者在稳定边界停下，记录停止及交出回执；打包期间复核文件未变 | 可以生成待审阅交接记录；源端是否停止未知就不能激活目标。停止实现工作不冒充冻结所有设备的记忆输入 |
| 目标核验 | 验证设备/任务授权、包身份、目标已持久化的记录及确认位置，重建同一 base+delta，核验与记忆快照的对应关系。并发 checkpoint 单列；缺关键记录、旧恢复世代或冲突未决不能宣称接班就绪 | 仅展示已有材料及缺口，不执行实现。可以按原接口核对来源，不能扫描/传送整库补齐未知 |
| 显式开始 | 已有源端停止回执，owner 对此交接 ID、目标及范围明确授权；目标记录实际会话/job。开始前再查交接是否已有活动目标、源状态及所核快照是否改变 | 同一交接已有 job 则返回已有状态，不再启动；无法查证时停下。收到记忆不能直接转换成“继续执行” |
| 结果取回 | 目标在稳定边界停下，交回准确 candidate/delta、测试与证据、实际记忆 ID/修订/确认位置。Mac 保留已有新工作，先导入独立 worktree 核对差异；owner 明确交回执行权后，原聊天主动重读 | 收到、集成、验收分别报告；冲突由已授权执行者处理。原聊天不会自动合并远端聊天历史，也不共享 harness session ID |

源端失联或 Mac 合盖不是停止证明。没有先前有效交出回执，就不得自动接管；owner 需经已授权通道核实并停止原执行者，或等源端恢复。人工记录不防止失控进程，不能宣传为技术单写入者保证。

记忆同步和代码传输可分别完成；目标开始时必须满足同一交接边界。存在无关离线尾部时，仅在 owner 明确接受已展示的缺口、工作不依赖缺失约束/结果、且其余开始条件均成立时，才能批准从最后可证快照做有界工作；否则只读等待。

## 4. 失败、复制、恢复与 Botmux

- **丢失写入回执**：先在原 ledger/世代核对已有请求。按原 helper 合同显式重放同字节请求，沿用 key/client/run/time；没有 owner 重试授权不循环 apply。不能换目标账本、新 key 或跨机重提 record 来“恢复”来源 ID。源端 pending 未决且影响交接边界时停止交接；跨机变更接收及持久确认由 #672/#674 解决。
- **快照移交中的 pending**：路径 B 先在源账本查明影响快照的未决提交，再停写取一致快照。经 owner 授权可移交最小原请求与收据供核验，不搬会话库或全部 state_root。原 pending.json 绑定旧包/配置/账本身份，不能直接复制到新路径 apply；若仍需跨机恢复未决提交，先另行冻结恢复接线，不能假定已有支持。
- **备份与复制**：backup/restore 验一致快照及新路径恢复；任务复制另验所选 task 的来源 ID、修订/撤回、确认位置和失效关系。现有 export 可含同一 task ledger 内多个任务；JSON 不是已有 restore/import 输入，restore 拒绝覆盖活跃库。色卡种子在合成副本内筛选不构成生产单任务迁移能力。路径 B 只用于 owner 明确批准的整库迁移或完全隔离的单任务源库；不能合并两端更新，不能默认搬走共享整库。
- **离线并发**：第一版拒绝自动合并两个离线可写副本。后续任务级复制即使收到了两端记录，也须保留来源 ID 和并发 checkpoint，由 owner 显式确认当前进度；不能按到达顺序选赢家。
- **恢复后**：先核任务身份、新账本世代、pending 和当前撤回标记，重新取得需要的 binding/发布授权；旧回执不推进新世代确认位置。完成核对前不向外发布“当前”。旧备份是仅存副本时只报告最后可证位置和未知尾部。
- **订正/撤回与缓存**：新会话/切换任务先读一次；操作前检查所用材料是否仍有效。写入、收到变更或恢复后需重新读取受影响记录。跨机传播仍依赖同步实现，未传播不能说另一端已失效；本地已撤回内容不能从旧 Lens 输出重构。并发进度未由 owner 确认汇总前不选单一赢家。
- **Botmux 绑定**：现有群/话题须明确映射 owner、task、repository、目标设备/harness 和活动交接 ID。只支持本合同的准备、查询、经明确授权继续、结果返回这些语义，不新增机器人平台或队列。重复“继续”沿用交接 ID 与已核 job；消息无法准确关联时先澄清。迟到报告按原交接归档，不能覆盖较新执行权或重新启动。真实去重接线未验证前，由 owner 逐次查询确认，不能把提示词说成可靠去重机制。

## 5. 八类故障桌面推演

这是 **设计推演的输入/状态/预期结果**，不是同步实现的测试回执。R/B 是合成的红/蓝卡原 ID，B10 是与前十条记忆边界配对的代码快照；字母不是真实 task/record ID。

| Case | 输入与可观测状态 | 必须得到的结果 | 依据及待实现依赖 |
| --- | --- | --- | --- |
| H01 正常往返 | Mac 在快照 K 停止并交出；目标确认 K 的代码与记忆边界，owner 授权；目标完成候选 L 并停止，随后交回 | 只启动一个目标 job；返回 L、测试及实际记忆 ID；Mac 导入独立 worktree，原聊天重读 L 对应记录。收到结果不等于已集成或验收 | 现有 handoff/collect 与显式内容读回；跨机原 ID 和确认位置依赖 #672–#674，真实往返另验 |
| H02 重复“继续” | 同一交接 ID 已有活动 job J；重复到达同一语义消息，或旧结果迟到 | 查到 J 就返回 J 的状态，不启动 J2；迟到结果不改变新执行权。查不到可靠状态则停住，不猜“没启动” | 现有路由/会话查询按实际能力使用；交接 ID→job 的去重接线是后续接口，不宣称已有 |
| H03 源端未停 | Mac 仍在编辑/运行，或源端断线而没有停止回执 | 目标最多准备/只读，不开始实现；owner 确认源端停止并复核快照后才继续。不能由超时推断已经让出执行权 | 现有工作状态检查与人工授权；没有自动租约/fencing |
| H04 传输中断 | 目标仅收到部分 delta 或记忆批次，摘要不符/确认位置尚未覆盖目标边界 | 保留最后验证快照，标记未就绪；不应用混合 patch、不执行未核脚本。显式恢复传输后按同一选择/摘要复核；有序缺口按连续位置停止 | 代码校验复用 handoff；任务级事务接收与连续确认依赖 #672/#674 |
| H05 写成但回执丢失 | 源端本地提交请求 P 后响应丢失；或目标已持久化变更但来源端未收到确认 | 本地在原身份下显式重放 P，返回同一记录而不新增；同步只能原变更身份去重并重发持久确认，发送端仍显示旧可证位置直到确认。未决结果不报告已收齐 | 本地幂等已实现；跨端原 ID 与持久确认依赖 #672/#674，不能拿 record 的 accepted 充当复制回执 |
| H06 回 Mac 时有新改动 | 目标返回 L，Mac 原工作区已有新提交/脏文件，或新的 owner 约束 | 保留两边；在独立 worktree 比较原 base、L 与本地新变化，报告冲突。需新授权/新快照时重新准备，不 reset 原工作区、不把旧远端结论当当前 | collect 的保留/核对流程；当前约束以实际重读为准 |
| H07 合盖前未同步 | 源端已本地保存 12 条，目标只确认连续前 10 条及 B10；源端离线，未通告总数 | 目标只展示这 10 条、B10 和最后确认位置，尾部标未知，不显示“已齐 10/10”或猜出缺两条。只有源端已有有效交出回执、代码吻合、owner 接受可见缺口且工作不依赖未知材料，才可从该位置有界继续；否则等待。源端恢复后原聊天主动重读目标进展 | 本地持久读/代码核验可复用；持久确认依赖 #674。无停止/授权时失败停止，不承诺零丢失 |
| H08 跨 task 混入 | 同一 ledger 含任务 T/U；T 的交接里混入 U 的记录、delta 或另一世代回执 | 在读/写/应用前拒绝混入并保留原状态；T 的确认位置不前进。不通过整库复制补救；权限缺失、伪造来源/旧世代同样停住 | 现有 task 读写隔离与路径核验；批次设备授权/原 ID 过滤依赖 #672，确认归属依赖 #674 |
