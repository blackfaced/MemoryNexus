# ADR-030: 当前有效知识维护

## 状态

**产品方向与阶段顺序已由 owner 于 2026-10-26 接受；精确接入合同于 2026-10-27 完成审阅并冻结。**

本决策将 [#317](https://github.com/blackfaced/MemoryNexus/issues/317) 纳入
MemoryNexus 的核心能力规划：先验证订正能影响后续实际工作，再推进跨记录整理与管理页面。
它不是整项功能已实现、接口已接受或生产部署已完成的声明。首个合同任务为
[#318](https://github.com/blackfaced/MemoryNexus/issues/318)，其
[冻结合同](../docs/current-knowledge-contract.md) 与
[验收矩阵](../docs/acceptance/current-knowledge.md) 已完成文档审阅；runtime 与实际接入仍需分项验收。

## 背景

用户纠正知识后，Agent 仍可能读到旧说法：订正被写成另一条普通记录，文档只追加说明，
或者账本已更新但客户端仍注入旧副本。仅要求 Agent 遵守提示词，无法证明订正已经生效。

核查基线是 main `955f1c53ea1f5fb14cad03fb1e6c31aa8005662c`（#316）。ADR-028/029
已交付替代链、依赖失效、current 过滤、来源版本、独立 consumer 和受管文档替换。
缺口主要是实际读取接入的完整约定、跨 ID 关系治理和真实使用证据，不能重建已有内核。

## 决策

### 1. 产品目标是让订正持续影响后续工作

MemoryNexus 维护有来源、适用范围和修订关系的当前知识，并让 Agent 在实际工作中使用它。
验收需要同时看到内核状态、实际交给客户端的材料，以及客户端据此完成的无害验证动作。
页面、关系数量或存储条目数不作为产品价值的替代指标。

这里的 current 表示在已观测版本及已知关系下仍可用，不保证客观真相或外部世界始终未变。
source-reported、execution-reported、owner-confirmed 与候选保持区别；未解决冲突显式呈现。
新写入时间、相似度、模型置信度和长期未使用都不能单独构成取代事实的依据。

### 2. 复用 ADR-028/029 的权威内核

继续使用 Rust CLI、stable JSON、SQLite task ledger 和版本化 workflow runner。
Skill/Lens 提出语义判断；CLI 校验身份、版本、依赖和既有确认规则；接入层处理外部文档与
客户端入口。任务隔离、同一 OS owner 信任边界和个人实验 ledger 的独立性保持原合同。

明确订正复用 `correct`：旧记录成为 superseded，新修订生效，依赖旧版本的结果失效。
内部保留历史与当前视图原地更新可以并存；不要求删除修订链或把私人账本历史放进 Git。
撤回仍遵守已有正文清除和 tombstone 语义，不能通过历史页面、缓存或新导出重新暴露正文。

普通 `record` 不会理解“更正”二字；用它追加矛盾说法不会自动形成替代链。一个修订链的
唯一当前版本也不等于跨 ID 的事实唯一。第一阶段必须展示这个限制，不能声称已解决。

### 3. 按三阶段推进

1. **订正到实际读取。** 先覆盖明确目标 ID 的订正、依赖失效、当前内容读取与外部副本
   核验。在一个仓库中证明新会话使用新内容，旧副本未协调或无法观测时明确报告缺口。
2. **跨记录整理。** Lens 提出重复、替代、冲突和适用范围关系，保留理由与来源。
   自动折叠、退休或改变默认读取需要明确的授权及可测试合同；疑似标签不直接改变权威状态。
3. **管理页面。** 先围绕单条知识时间线、局部关系、待处理项与实际读取预览提供可解释性。
   页面读取同一内核；写入口复用相同确认与版本校验，撤回正文不得重新出现。

第二、三阶段保留在 #317，待第一阶段真实使用反馈后再冻结各自接口与实现任务。
第一阶段不以新 UI、语义检索平台或通用知识图谱为前置条件。

### 4. 读取接入必须覆盖实际材料

现有普通 `context` 排除所有 draft，包括经 `correct` 的 draft；repository consumer
输出也不会自动进入普通 context。第一阶段合同必须分别说明两条读取路径，不能通过
静默提升 trust 或混入草稿来掩盖缺失的接入。

默认当前读取和显式历史审阅应有明确用途。历史审阅可追踪 superseded 内容，不得将其
混作当前事实；stale/retracted 正文的现有保护继续有效。读取为空、失败或截断时应报告
缺口，不依赖隐藏客户端记忆补齐。

客户端入口应保存有界、私有的读取证据，证明它实际拿到哪个任务、哪个版本和哪些材料。
字段、存放位置、并发复查规则及精确 argv 由 #318 冻结；该证据不是第二个权威记忆库。
无法核验的 harness 注入状态显示 unknown，不能由账本正确推断已接管所有输入。
已运行会话里读入的旧上下文也不能被承诺自动删除。

hook 用于强制执行入口检查，wrapper 的保证只覆盖经它启动的会话，提示词仍是 best effort。
关键词检查可作为提示，不能替代身份、状态、依赖与实际读取核验。
当前 confirmed 字段及摘要是可信本地调用者的声明，不能声称已经实现独立人类认证。

### 5. 复用既有安装与真实验收

- #312 继续负责固定安装和外部调度接线；本规划不安装、不迁移私人账本或改调度。
- #301 继续负责真实 MiniMax↔Codex 双向交接与 owner 判断。
- #313 继续负责一个真实仓库、双 Lens、外部输出和实际 scheduler 证据。
- #283 的十四天个人实验标准不变，也不提前触发 #284–#286。

现有 [#301 验收记录](../docs/acceptance/task-memory-cross-client.md) 已报告部分真实
MiniMax 会话及定时运行证据；完整 Codex 路径与 owner 决定未完成。保留这些证据的原版本
和适用范围，不将其重置为全部未运行，也不推断它证明了尚未实现的新接入。

## 后果与边界

正面：明确订正可复用现有机制，优先验证用户是否减少重复纠正；外部副本与真实读取成为
验收对象，能够区分“保存成功”与“下一次工作实际使用”。

代价：需要处理文件与账本不同步、运行时入口差异和多次读取间的版本变化；语义等价与
冲突裁决仍需证据和授权。第一阶段接受有边界的保证，不承诺接管所有客户端或旧会话。

不引入新数据库、常驻 scheduler/daemon、模型 SDK、通用 connector、全局事实唯一键、
跨项目自动归纳或 legacy HTTP/Surface/Lens 服务。本决策也不批准管理页面的运行方式。
